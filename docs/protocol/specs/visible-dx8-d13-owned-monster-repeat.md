# D13 owned monster physical repeat

Status: OPEN, source implementation in progress; no execution or client acceptance. Profile: VisibleDx8D13. This is an ordered runtime operation, not a crash-atomic transaction.

The existing player repeat receipt requires two admitted player bindings. Monster combat must not invent a target player or borrow that receipt. A new private issuance is tied to an actual completed physical monster hit, its original admitted Frame actor, and the exact registered monster birth/incarnation and catalog family. Initial arm follows successful real damage, XP and any level query/output; failure cannot create repeat authority.

The due worker acquires the Frame's real exclusive operation before it captures a due generation and revalidates the exact actor, native request, current attack-speed cache, registered target object, family metadata, alive state, map/dynamic identity and current physical range. It re-enters the real Frame route with its actual request; no public synthetic ticket, fake acceptance callback or recursive public Frame operation is permitted. The generation-specific terminal cleanup must not retire a replacement request. Death, respawn, removal, UID reuse, replaced registration, disconnect and an unproven family all invalidate the old target. The actor's ordinary movement/cancel and retirement semantics must apply to the monster variant too.

The target proof uses the actual birth state held under MonsterRuntimeStateStore's own gate, including its existing `ClassicBuffIncarnation` identity that rotates on actual respawn, and exact captured family values. Dynamic targets retain their actual registry entry. Static targets require a unique real catalog materializer match, exact spawn owner and retained spawn attributes; neither a numeric UID nor a fabricated dynamic registration suffices. Current hitpoints/coordinates are observations rechecked when due, not frozen snapshots. The proof itself does not arm, spend, damage or grant XP.

Tests must use genuine admitted actor and registered live monster: actual initial physical Frame hit that earns a level, real completed equipment query and HP restore, then actual due worker repeat under its exclusive lease. Include registration replacement/UID reuse, death/respawn, movement, cancellation and disconnect refusals; no raw native or ticket setters. Source and fixture controls require the actual reference and selected D13 profile; none establishes live-client parity.

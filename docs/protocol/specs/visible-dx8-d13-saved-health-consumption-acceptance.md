# Saved health consumption observation

Target profile: VisibleDx8D13. This tooling reads the actual owned DataTool inspector; it sends no client packets and introduces no wire evidence. Base: public source 2fa26cf8f2660062099e9fc68eef3dae8940626f, independently of the isolated native HP/health runtime work.

Add the twelfth acceptance family, `consume-health`. Both initial and Resume invocations run only `inspect-owned-player`. No input, save, grant, dispatch, source gate, automatic retry or lifecycle action is authorized by this scenario. Exact potion UID/type and expected saved HP are explicit and retained in owner, strict intent and receipts. Existing nine-argument character projection constructors retain compatibility through trailing nullable vital fields. Actual inspection supplies MinHitPoints, MinMana and MaxMana from valid integer attributes of the already-decoded saved image; absent MaxMana stays null rather than using the runtime parser's MinMana fallback (invalid required integer text already refuses inspection). Missing/null vital evidence refuses qualification rather than becoming zero.

Initial inspection must be complete, bounded, stable and digest-capable. The selected UID occurs exactly once as an inventory row, position/warehouse zero, with an explicit known legacy health type. Expected HP must differ from the initial saved HP. Resume checks retained identities, hashes and exact intent before its sole inspector command. Selected saved HP must equal the expectation and change; map, position, body, class, level, gold, CP and both saved mana values remain equal. No healing formula or full-HP consumption rule is inferred.

One unit is consumed. Native stack zero means one unit: initial stack zero/one requires the selected UID to disappear and inventory/physical counts to decrease by one; larger stacks retain the exact UID/type/row with only stack decremented. All other summarized item rows, all mail rows, and other counts stay identical; UIDs remain globally unique across all seven real containers and deposited rows. Truncated/count-only/digestless projections refuse. Spells, Proficiencies and Mailbox presence, length and complete image digests remain equal. Character and Items must remain present with valid image digests and their digests must change. Complete byte images are observed, but unchanged opaque bytes inside the modified Character/Items images are not proven by this projection.

`SavedHealthConsumptionObserved` exits 2, retaining LiveClientVisualPending, WirePending, SourceGatePending and liveStoreSynchronized=false. Status rechecks the pure transition and retained intent, never trusts an editable PASS field and never invokes an inspector. Local JSON and hashes are editable consistency evidence, not authenticated attestation, runtime atomicity, live Store, wire/client, SQL or power-loss proof.

Regression source must invoke actual PowerShell and actual DataTool on genuine owned temporary fixtures. Cover native last unit zero/one and stacked success, wrong HP/type/row/currency/sidecar, missing/null vitals, real truncation, identity/intent changes, and initial/Resume no mutation or dispatch. Root alone builds and runs it; this package makes no execution claim.

# Owned native items: Store publication participant

2026-10-30. Implements the Store/admission phase of
[the native item graph join](owned-native-item-graph-join.md), baseline 5362feb1.
The selected production profile is old7899 / VisibleDx8D13. No new packet,
client-field mapping, global native catalog, SQL or native combat activation.

The actual Frame's readonly WorldDataCatalog and selected profile supply the
scoped constructor evidence. A saved UID is never an issuer. The existing
LegacyOrdinarySpellBinding retains its real Store, connection, holder identity,
player/client, spell/proficiency owners and Recovery; the native item graph and
canonical item snapshot are additional participants in that same binding.

First admission prepares the image and all seven real containers while slots
are absent and the genuine prefix still owns its planned UID. Preparation occurs
inside PreparedOrdinarySpellAdmission, before the existing joint admission
writer. The actual prefix adopts its UID before assignment-only graph/spell/
vital/holder publication. Partial or foreign preexisting container slots refuse;
no placeholder owner is installed. The canonical FinalSnapshot is published by
reference in both the final WorldSession and binding.

PreparedSessionSpellPublication handles later Set/CAS, persisted single/pair,
login completion and existing central spell/status publication users. Before
any new metadata callback, it validates the last published graph through its
real actors. The next image always receives that exact Graph.Image as BaseImage.
SourceSnapshot must be the exact proposed PlayerItems; the graph and holder use
the selected image's canonical FinalSnapshot. Identical images retain native
objects and containers. Prepared native state, before/after witnesses, required
metadata/conversions and collection preparation precede actual writer calls.
Assignment-only leaves publish graph, binding snapshots and holder after the
corresponding complete pure proof. Pair paths retain the Store's existing
ordered connection gates; no new cross-player ordering is introduced.

Holder.Clear calls the existing binding's Retire, which retires the joined
graph and clears only its exact slots. Escaped real containers keep permanent
joined/retired tags; replacing a public field cannot restore an unbound writer
path. Wholly unbound/manual Store behavior remains separate compatibility and
is not presented as native item ownership.

The existing mailbox package receipt is a necessary late preparation boundary.
Its actual final UIDs do not exist before reservation. The Store therefore
issues a closed, single-use PreparedMailboxItemPublication under its exact
holder/actor lease. It accepts no saver or accepting-validator authority:

1. ValidateItemIds consumes the actual prepared grant ItemIds and scoped catalog
   evidence before the real recipe's first UID intent/reservation.
2. After that same real receipt materializes the final item snapshot, Prepare
   creates the complete native publication and returns its canonical session.
   The caller captures canonical item persistence/output proofs before writing.
3. ArmBeforeCommit completes callback-bearing validation and arms/consumes the
   before-writer proof after actual package work preparation, before TryCommit.
4. After the genuine joint writer succeeds, the Store consumes the after proof
   and publishes native state and that exact returned canonical holder.

Failures after a real intent/reservation retain the existing operation and UIDs.
The actual package owner's admitted/committed flags and Recovery handling remain
in force; there is no refund, intent deletion, UID reissue or fake uncommitted
success. A committed owner/proof loss retires the real holder and blocks its
existing Recovery. Existing native package class/Ninja/gear publication and wire
order are preserved rather than replaced with an accepting stub.

Explicit persistence distinction: generic Set/CAS already publish native/holder
state before their concrete Frame persistence postlude. That postlude still has
per-file best-effort item/scalar IO paths that log some failures; only exceptions
escaping those helpers receive the existing typed publication/fencing handling.
This milestone does not repair that generic durability gap or advertise these
APIs as prewriter file transactions. Actual persisted single/pair and package paths
prepare native state before their real writer and publish only after success.
Root separately adapts exact canonical final-session continuations in the real
mail/equipment/drop/sale/trade callers. No UID/value-equality identity fallback
or global proposal-to-final alias registry is introduced.

The raw startup equipment observation remains historical observation; this join
does not silently turn it into a current native combat authority. Public raw
field/map observers and noncooperating writers remain outside a global atomicity
claim. Native graph proofs detect drift before the next owned operation, and
joined entry writers are fenced by their real owners. This is not SQL, power-loss
or process-crash atomicity.

Helpers A/B and Root author separate finite controls. No helper built, tested,

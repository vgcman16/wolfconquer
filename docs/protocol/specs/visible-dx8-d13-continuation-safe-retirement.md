# Continuation output loss and safe actor retirement

Target: existing VisibleDx8D13 XP/level/stat, equipment-query and HP output
sequence. This change adds no packet or replay identifier. Source-only draft;
the coordinator must qualify it with the actual earned-award reconnect fixture.

The current continuation failure path blocks the world's recovery domain even
when its last Character replacement is fully verified and the only failure is
delivery. The observer path can block before the query adopts its published
holder. A restart can recover that saved award, but a same-runtime reconnect
cannot pass the unnecessarily blocked domain.

Each concrete continuation writer records a private cleanup checkpoint after
its verified durable/native/holder publication and before calling observers.
Credit and published ordinary-admission origin start the lineage. Actual step,
query proposal, derived journal23, phase, restore and final-clear writers advance
it from the exact preceding holder. A checkpoint grants cleanup only: it cannot
authorize a query, refresh a gameplay receipt, credit XP or clear a recovery block.

Retirement requires the same real Frame exclusive operation, original native
binding, latest registered exact holder and current native scalars. Under the
existing lifecycle/package/connection/native/actor order, then the sorted file
coordinator set, it rechecks the complete retained Character image and marker,
the actual saved Spells image, and any retained journal23 Items image. Saved
Character comparisons allow only the established runtime StatusFlags, XPCount,
Stamina and Vigor distinctions; all other persisted fields remain checked. The actual
configured recovery owner must already be ready and its journal clear. No file
is rewritten and no recovery state is unblocked.

When those proofs hold, clear only the exact actor and retain a cleanup receipt
so nested catches of the same propagated exception object do not subsequently
block the domain for the same retirement. A different later failure cannot reuse
that historical result instead of proving recoverability.
The original exception still propagates. A replacement binding is never cleared.
The actual monster-hit finish path consumes this private historical result once,
under its lifecycle gate, only for its registered attempt's original actor,
the same still-held exclusive operation and the identical propagated exception.
It then abandons that attempt without blocking the already-proved recovery
domain. This closes the outer catch that previously blocked again after safe
retirement; it performs no fresh cleanup, file proof, holder refresh or unblock.
Missing/stale images, native drift, pending journal, stopped/changed operation,
or any persistence/publication uncertainty keep the existing global block.
Exception class alone never selects the safe path. An observer receives no
special mutation authority; its unpublished or corrupt changes invalidate proof.
Actual transport EOF has a separate retirement-only lifecycle proof: the same
Frame's registered creation/transport-close callback must have ended that exact
connection while its original exclusive operation remains active. The proof
can substitute only for the live lifecycle predicate in cleanup; exact latest
holder, native state, pending marker, retained full images and clear journal
remain mandatory. It also bounds reuse by the outer catch of the identical
propagated failure. Normal gameplay/admission currentness is unchanged, and
ended transport alone cannot retire a replacement or avoid a recovery block.
If proof fails after the real query has already published another holder, the
denial path still retires the original binding/native identity under actor gates
and blocks recovery. It does not require the driver's stale pre-query holder,
and does not convert the newly published holder into a gameplay capability.

Initial admission failures before a registered startup query remain conservatively
blocked by the existing admission fallback. This draft does not claim all query
steps are crash-atomic, exactly-once fresh wire requests, or live-client acceptance.
Required qualification includes earned first-level output interruption and
same-runtime reconnect without recredit, plus real file/native drift, journal,
observer-before-adoption and replacement-owner negative controls.

# Owned equipment query: native combat status publication

Target: VisibleDx8D13 managed offline server; depends on the actual owned ordinary admission and native binding and on Vigor15's query completion hunks. The five mapped fields are explicitly named by both the existing managed query packet and LegacyNativeMsgStatus: MaxAttack, MinAttack, Defence, MagicAttack, MagicDefence. Other native fields, including all remaining packet values and death-query publication, remain outside this change.

The actual equipment-query executor constructs its actual status frame and captures those five sent values and the native Status identity and before image while holding the current connection and native actor gates. After the existing full status/HP/postlude query, and before completion, the actual canonical current holder is recalculated through the same packet producer. The new preparation requires the same values, bound native Status object, unchanged five native before fields and current owner. The existing completed-query path then checks its real epoch, bound owner, equipment inputs, HP/mana overlays and status holder. A private query-issued token retains the emitted fields, epoch, exact holder, native Status and before-image. The maximum publisher consumes and revalidates it before publishing any maximum or completed-query capability, then writes both maxima and the five fields with plain assignments and marks its inert completion published. Existing Vigor, level and admission continuation checks occur afterward and remain unchanged. Unbound queries retain their existing path. A denied query does not reach the publisher.

The before image detects a current value drift or Status-object replacement. It is not a versioned mutation history and cannot establish absence of an external change followed by exact restoration. The added checks do not authorize native calls or make a new public capability from a UID, saved data or a raw value alone. Completion's original HP/mana writes and other stages retain their existing ordering; this change does not claim transactionality across an exceptional failure of those existing writes.

Owned public-frame regressions exercise the actual completed packet/native holder, in-send native scalar drift, native Status-holder replacement and actual FineRain denial, with file checks. These source-only proposals have not been built or run. FSB296's native attack/defence gap remains an open finding pending Root's review and verification; no live client, broader status parity, saved behavior, or death publisher coverage is claimed.


The issuer token is privately associated only by the real query executor. An unassociated token cannot alter or invalidate a real prior completion. Actual in-send Status drift and Status replacement controls check that a started query has no current maximum completion or Vigor qualification after refusal; a true complete query control checks both. These source tests are proposed and unrun. The in-send control observes drift before final preparation; it does not independently exercise a timing gap after token creation, because there is no fabricated callback between preparation and the maximum publisher.

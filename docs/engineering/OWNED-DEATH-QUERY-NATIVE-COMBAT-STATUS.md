# Owned-death query native combat status

Target VisibleDx8D13 managed/offline path. Depends on the separate ordinary-query combat-status5 proposal and its exact `WorldPacketHandlers.CombatFields` helper; the sole helper changes here are exposing that already-existing nested immutable type internally and adding its five-field write. Root must merge those narrow helper changes atop that proposal and preserve all Vigor15 query hunks.

The real private owned-death builder runs its own death prefix, equipment query admission, stat/rune calculations and native magic query arithmetic. For an admitted query it constructs the historical status packet it will queue for the actual target. Its named MaxAttack, MinAttack, Defence, MagicAttack and MagicDefence fields are carried as immutable data in the existing decision-bound `OwnedPhysicalDeathQueryValues`. No ordinary query receipt or send callback supplies this data. A denied death query has no such tuple.

The existing `OwnedPhysicalDeathPublication` binds the real target binding, native Status object, prepared death result, exact canonical target, native query entry and epoch, and actual HP/mana overlay. It captures the five native before fields, requires them unchanged alongside the existing native maxima and owners before the real writer, and writes the prepared fields on the same Status object during the already-guarded native publication. The genuine published receipt also verifies the same five after fields. A denied query preserves the captured before fields and no new value is issued. All existing journal, HP/mana, attack speed, perfection, query epoch and native holder safeguards remain.

The real earned-FineRain kill regressions compare native fields observed before the first death-clear frame with the actual later death status packet, preserve full journal/files and native maxima checks, and exercise real post-publication native defence drift causing output fencing. A separate existing real early FineRain denial occurs at required level-query admission before death and now checks native combat fields remain unchanged. Its earned registration is cleared by normal death before the actual death equipment query, so it is not evidence for an actual denied death-query branch. Existing closed journal interruption has no callback between preparation and its writer; a deterministic genuine pre-writer native field drift control is not supplied here. Source guard coverage alone is not test proof. The raw before-image also cannot detect an external change followed by exact restoration.

This is an unrun source proposal. The FSB296 combat-status gap remains open until Root reviews integration and validates the real kill, denial, receipt drift, journal and maxima checks. It does not cover other native Status fields, native client operation, live acceptance or full parity.

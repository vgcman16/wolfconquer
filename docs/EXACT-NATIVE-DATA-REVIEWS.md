# Exact native data-file review scope

Two local schema2 review categories cover only `ini/userdata.lua` and
`ini/luacfg/userdata.dat`. Each needs its exact case-sensitive path/collision,
file node type, positive bounded length, source SHA256 and explicit evidence.
All other filename quarantine rules remain. No token_type.dat category exists.

These are publication-input rules, not packet/catalog decoders or client changes.
No signed-manifest schema, install/repoint behavior, runtime profile, protected
configuration, source-update policy or default activation changes.

## Evidence and limits

A bounded complete strict-GBK/GB18030 review of the current small Lua file found
server-classification state, functions and aliases. It defines default mutable
in-memory fields and calls an external Cpp_And. No direct account/auth/file/network/
machine-path access appeared in that script; external caller behavior is unknown.
The exact staged luacfg/userdata.dat matched retained official patch7892–7930 bytes.
This supports a candidate asset role/provenance, not a decoded binary table layout.

Generic source contains no copied script/data, actual client digest or native
constants. Each operator must review their exact proposed contents; a filename,
extension, category or supplied hash does not establish privacy or semantic safety.
Changed versions need a new review and digest. The unrelated token_type.dat format
remains unresolved and quarantined. Opaque portable startup configuration remains open.

## Preserved controls

- Metadata planning still reads names/types/lengths only and carries the supplied
  review digest; it does not create or authenticate that content review.
- Staging checks held source bytes against the digest and destination readback.
  Only sourceRoot is rebased; all review fields and prior-install baseSha256 stay.
- Publisher API and CLI validate the closed review shape before source/key work,
  then compare actual source length/digest before outputs and copied bytes before
  blob promotion. Digest checks do not replace path/reparse/membership validation.
- Missing/unused/conflicting review, wrong category/path/case/type/bounds, backup/
  private/AutoP paths, aliases and changed bytes remain refusals. A source hash
  never substitutes for baseSha256 or authorizes adjacent files/directories.
- Existing obj/BMP categories and schema1 behavior remain unchanged. No generic
  waiver, payload rename, bypass option, fake owner or accepting callback is added.

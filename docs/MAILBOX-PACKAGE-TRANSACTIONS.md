# Mailbox package transaction owners

This is an explicit internal integration prerequisite. The production Host does
not create the package producer or enable these payouts automatically.

The allocating ranks1-9 path validates the complete action before retaining its
UID recipe. The actual registry intent and receipt bind the same operation and
range across retry. Complete Character, Items, Mailbox and CombatGear images use
the existing four-file v5 journal; native/session state and packets follow that
commit. Full bags produce the established error with no partial wallet reward.

A closed prepared/completed work record binds the immutable intent, range and
four exact before/after hashes. Fresh startup reconciles retained journal work;
unknown, mixed or missing required images refuse. Completed work is retained.
An in-process fence also covers the interval before the real Store publishes the
committed session, including ambiguous completion-write failure.

Pending work admits only its exact retained request and PIN verification. Normal
Store, mailbox cache, snapshot and journal writers refuse conflicting changes.
Packet admission wraps actual registry delegates and holds/rechecks actual world
leases. Disconnect cleanup retains its own ordinary lease and can retire owners.

Recovery startup loads exact raw saves before normal normalization or Online
writes. Genuine cold native preparation publishes bounded saved fields under the
actual Store identity. Saved PIN validation precedes that publication; verifying
PIN changes admission without rewriting the saved PIN. No normal runtime loop or
autosave starts while work remains pending. Special Ninja/Pirate owners are not
invented when their actual loading prerequisites are absent.

Delivery completes catalog/managed-state traversals before its final current
Store/PIN/native checks. If a callback retires or changes an owner, later packets
stop; the durable committed payout is retained rather than rolled back or paid
again. This is not an atomic network-send guarantee against later independent
retirement.

Focused evidence is recorded in VALIDATION.md and FSB-101. Owned files, genuine
C# runtime components, actual Frame/registered handlers and captured transports
are used. Pirate contract controls run in fresh processes with actual table.Load.
They do not prove the native executable, live client, SQL or production Host.

Remaining work includes stack/color fidelity, explicit no-allocation work,
flags10-12 with their real reward participants, full native Inventory/wallet/save
adoption, runtime resumption after recovery, secure native login and actual-client
acceptance. Whole-game/complete-English parity and full-client distribution are
separate unfinished requirements.
